# apycula chip databases

apycula's chip databases are generated by fuzzing Gowin's vendor tools, so a
git checkout of `third_party/apicula` has none. These two are copied from the
build of the pinned commit, so the toolchain builds without Gowin EDA:

- Source: `linux-x64-gowin-data.tgz` from apicula's rolling `0.0.0.dev`
  release (uploaded 2026-11-11T20:14:26Z by the CI build of `20d6af9`,
  tarball SHA-256 `5fc0d96900f3f1466a185fa9d551ecb975046b3d81611d0dbe252a5d7ce8aec4`).
- `GW2A-18C.msgpack.xz`: the Tang Primer 20K's device (nextpnr, gowin_pack in
  our Makefile). SHA-256 `d1a9d4d3c24d477195d0f74eac43f03aa8ff560720a57f5e8ae8e452a411beca`.
- `GW2A-18.msgpack.xz`: the family name other projects pack with
  (`gowin_pack -d GW2A-18`). SHA-256 `efcd46695338084d0743dd39e1372854e02fcf89b976eb06d781c7ba15b18439`.

When bumping the apicula submodule, replace both with the databases of the
new commit: take the `0.0.0.dev` tarball right after that commit's
"Chipdb builder" run (`gh release download 0.0.0.dev -R YosysHQ/apicula`),
check that the run built that commit, and update the hashes here. Then rerun
`tools/setup.sh`.
